# SafetyBox Roadmap

Milestones are sequential unless an ADR documents a justified change. Completion means meeting exit criteria, not merely creating files.

| Milestone | Objective | Deliverables | Exit criteria |
|---|---|---|---|
| M0 — Research specification | Establish traceable scope and evaluation design. | Governance, research, architecture, threat, experiment, and ADR documents. | IDs are consistent; links validate; open assumptions are explicit; implementation scope is approved. |
| M1 — Deterministic reference monitor core — Implemented | Establish a minimal fail-safe authorization boundary. | Typed interfaces, policy decision path, focused tests. | Met for the in-process `ReferenceMonitor` API: `INV-001`, `INV-002`, and authorization failure have executable tests; direct tool references remain outside this abstraction. |
| M2 — Task contracts and capability enforcement — Implemented | Enforce task- and resource-scoped authority. | Immutable task contract, explicit action/resource capabilities, deterministic evaluator, and focused tests. | Met only for the in-process logical model: task/action/resource scope and non-expansion tests pass; no contract schema, capability registry, or filesystem/shell adapter exists yet. |
| M3 — Canonical event and audit system — Implemented | Produce ordered, attributable, explainable records. | Immutable in-process event schema, per-session sequencing, ReferenceMonitor audit emission, and in-memory audit sink. | Met for the single-process in-memory `ReferenceMonitor` model: requests map to session/task IDs, decision rule IDs are recorded, ordering and failure semantics are unit-tested. Durable provenance remains future work. |
| M4 — Threat scenario simulator — Implemented | Reproduce controlled benign and adversarial action requests. | Immutable deterministic scenario runner, harmless in-memory tools/world, M3-linked raw evidence, starter TS corpus, and benign controls. | Met for the single-process logical simulator: declared step expectations, blocked/effect distinction, audit linkage, and semantic replay are tested. It is not a benchmark, real sandbox, or trajectory detector. |
| M5 — Trajectory monitoring — Implemented | Evaluate stateful signals across action sequences. | Bounded rule-based observational monitor, canonical event-derived observations, immutable findings, and sequence fixtures. | Met for the in-process M5 implementation: session/task isolation, ordering handling, bounded state, and initial `TRJ-001`/`TRJ-002` regression evidence are tested. No registered comparison experiment or general effectiveness claim exists. |
| M5.1-A — Deterministic trusted context model — Implemented | Represent externally trusted semantics without changing authorization or detection. | Immutable versioned task context, structured declarations and provenance, deterministic validation/lookups, and separation regressions. | Met for the in-process representation: conflicts and untrusted declarations fail, M2 scope semantics are reused, missing required dimensions are explicit, and context cannot grant capabilities. Context-aware detection remains future work. |
| M5.1-B — Deterministic context evaluation primitives — Implemented | Interpret one completed observation relative to trusted task context without trajectory reasoning. | Stateless evaluator, immutable reason-coded evaluation, provenance, and missing/mismatch/applicability regressions. | Met for single-observation metadata interpretation: resource, destination, action-purpose, fallback, and supplied logical-flow relationships are evaluated deterministically; authorization and M5 remain unchanged. Stateful context-aware trajectory reasoning remains future work. |
| M5.1-C — Deterministic context-aware trajectory reasoning — Implemented | Interpret ordered observations using trusted structured context. | Separate bounded monitor, immutable context-aware findings, contextual egress and fallback-aware denial rules, and development contrasts. | Met for the in-process candidate implementation: state is ordered and session/task isolated, M5.1-B evidence and provenance are preserved, missing context abstains, and authorization/M5 remain unchanged. Development cases are contaminated; detector freeze and held-out corpus authorship remain next. |
| EXP-013-B2 — Frozen executable single-observation baseline — Implemented | Provide the mandatory history-free comparator before held-out corpus authoring. | Versioned stateless classifier, immutable audit results, commutative idempotent scenario reduction, tests, and architecture documentation. | Met for `B2-SINGLE-OBSERVATION@1`: M5.1-B mismatch/consistent/insufficient/not-applicable statuses map explicitly; order, duplication, and sequence values do not affect prediction; no M5.1-C or authorization dependency exists. |
| EXP-013-B4 — Bounded contextual trajectory candidate — Implemented and frozen | Add the preregistered ordered history primitives required before EXP-013 corpus authoring. | Separate immutable history schema, fixed bounded monitor/configuration, four generic rules, development-only B2-parity probes, and architecture documentation. | Met and frozen as `B4-BOUNDED-CONTEXT-TRAJECTORY@1`; EXP-013 later evaluated it on 40 held-out history-required counterfactual pairs, with the result and its limitations recorded separately. |
| Real Tool Mediation — Filesystem — EVALUATED AT BOUNDED FMED-L1 | Establish faithful observation, canonicalization, authorize-before-effect control, denial correctness, bypass testing, failure semantics, and audit reconstruction around a real isolated filesystem. | Frozen EXP-014 protocol, `FS-ADAPTER@1`, held-out corpus, one-shot results, validity analysis, and bounded synthesis. | Met only for named sequential isolated-Linux FMED-L1 sub-properties supporting RTM-1. Direct routes, TOCTOU, concurrency, real agents, and production remain outside scope. |
| Real Tool Mediation — Subprocess — AUTHORIZATION EVALUATED / EXECUTION NOT DEMONSTRATED | Establish direct executable/argv mediation with executable and cwd authority, no PATH or shell reinterpretation, authorize-before-spawn ordering, truthful partial-effect semantics, audit reconstruction, and explicit bypass/process-tree limits. | EXP-015 froze `PROC-ADAPTER@1` and produced 120/120 exact authorization decisions, but 50 expected-regular helpers were non-ELF scripts and ten other positives intentionally used invalid executable shapes; child spawns were 0 and intended benign completions 0/44. | RTM-1 remains unchanged. Next exit gate is a new EXP-016 with independently validated native fixtures and reached lifecycle semantics; EXP-015 cannot establish RTM-2. |
| M6 — Risk and capability degradation | Evaluate graduated containment. | Experimental state machine, degradation rules, recovery/approval protocol. | Transitions are deterministic and audited; weights, if any, are empirically calibrated. |
| M7 — Benchmark suite | Create a versioned benign/adversarial task corpus. | Benchmark manifests, tasks, scoring protocol, data cards. | Coverage and denominators are documented; licensing and contamination checks are complete. |
| M8 — LLM-monitor baseline | Add an optional comparison monitor outside the deterministic core. | B3 adapter, prompts, cost/token capture, failure handling. | Runs are reproducible where provider controls permit; deterministic enforcement has no dependency on B3. |
| M9 — Cross-model/framework evaluation | Test portability and generalization. | Multiple model/provider and framework adapters with matched protocols. | Comparison matrix has preregistered selection criteria and known confounders. |
| M10 — Ablation studies | Attribute effects to system components. | Registered ablations and analysis scripts. | Each ablation changes one declared factor and reports uncertainty. |
| M11 — Paper experiments | Execute the frozen primary evaluation. | Finalized experiment manifests, immutable results, analysis, claim updates. | Planned trials complete; deviations are logged; claims trace to evidence. |
| M12 — Artifact/reproducibility release | Package a reviewable research artifact. | Versioned code, data or retrieval instructions, environment lock, artifact guide. | Independent clean-environment reproduction succeeds and limitations are documented. |

## Research-program dependency milestones

These milestones refine the evidence path without renumbering the implementation roadmap
above. `RP-1` and `RP-2` are independent prerequisite branches and may proceed in
parallel; downstream claims require both where shown.

| Order | Program milestone | Dependency-sensitive exit criterion |
|---|---|---|
| RP-1 | `AUTH-COVERAGE-002` | New blinded corpus, zero pre-run held-out production executions, canonical crash-safe raw-first run, and complete stratified authorization result. |
| RP-2 | EXP-016 | Protocol@2 native-child corpus/run reaches positive execution branches and benign completions with truthful lifecycle evidence. |
| RP-3 | `UNAUTHORIZED-EFFECT-001` | RP-1 + RP-2 + bounded EXP-014 evidence support separate authorization, forwarding, bypass, real-effect, attribution, and utility results. |
| RP-4 | `AUTHORITY-MODEL-V2` | Formal delegation, attenuation, expiry, revocation, approval, issuer, and provenance semantics are frozen before runtime implementation. |
| RP-5 | `OWASP-AGENTIC-BENCH-001` | Only mapped subclaims backed by adequately mature authority and mediator controls enter the scenario suite. |

The governing order and parallelism are in
[`SAFETYBOX_RESEARCH_DEPENDENCY_GRAPH.md`](docs/research/SAFETYBOX_RESEARCH_DEPENDENCY_GRAPH.md).

Dates are intentionally omitted until staffing, implementation scope, and experimental resource constraints are known.
